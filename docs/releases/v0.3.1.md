# v0.3.1：供应商认证、向量维度与摘要有效性修复

## 最终行为

- 供应商状态依据真实配置计算，再构造独立脱敏响应。`api_key` 始终为空，`has_api_key` 表示是否保存，`secret_preview` 仅返回固定掩码。默认地址不会让未保存配置的远程服务显示绿灯；绿灯不代表网络连通、Key 有效或模型可用。
- OpenAI Compatible、llama.cpp 的 Key 选填；官方云供应商继续必填。有 Key 时发送 Bearer 认证，无 Key 时明确省略认证头，不读取 Worker 环境中的 `OPENAI_API_KEY`。
- Key 留空、空白、`null` 或省略字段保留旧值；非空字符串替换；`clear_api_key: true` 明确清除。清除与替换不能同时指定。前端支持清除 / 取消、必填 / 选填说明，保存后更新状态，重新打开模型设置时重新读取配置。
- **数据库仍为 `vector(768)`。** 统一向量入口覆盖 Ollama 和所有 OpenAI 兼容路径，拒绝空向量、非 768 维、布尔值、非数值、NaN、Infinity 及超出 float32 范围的分量。错误包含期望与实际维度。不截断、不补零、不修改数据库结构。
- OpenAI 兼容向量先检查原始 JSON，再交给 SDK 解析，避免 SDK 将布尔值转成浮点数后绕过检查。验证在向量入库及语义 SQL 前完成；混合检索也先验证，再启动两路数据库召回。
- 短摘要和普通长摘要的 `null`、空字符串、纯空白正文均作为失败。插件入库不再把模型异常替换成原文并标记完成；沿用任务现有失败元数据与 `pending_ai` 恢复路径。上传文档失败也不会覆盖已有摘要、写入完成状态或发出成功通知。
- 模型诊断仅记录任务、模型、耗时、`finish_reason`、错误码和异常类型，不记录 Key、原文或模型响应正文。空正文响应的实际用量仍按现有计费逻辑记录。

无需依赖或数据库迁移变更。

## 配置

llama.cpp 的供应商 ID 为 `llama_cpp`，独立保存在 `provider_config::llama_cpp`。原有 `openai_compatible` 的配置和任务分配 ID 保留。两者均可分配给标签、短摘要、长摘要及 Embedding；向量任务必须选择原生返回 768 维的模型。

- `http://server:8080`、`http://server:8080/v1/` 规范为 `http://server:8080/v1`。
- 保留已有显式反代 / API 前缀，例如 `/proxy/v1`、`/gateway/api`；官方供应商的 `/v1`、`/api/paas/v4` 等路径保持不变。
- Docker 中 `127.0.0.1` 指 Worker 容器自身，应填写 Worker 可达的主机地址。
- 免认证服务保持 Key 为空；旧配置已有 Key 时须明确清除后保存，空白提交不会删除旧值。
- `thinking_mode` 仅用于两个兼容供应商：`auto`（默认）不发送扩展参数；`disabled` / `enabled` 才显式发送 `chat_template_kwargs.enable_thinking=false/true`。仅对支持该参数的服务器使用。本次服务的 `qwen9b` 采用 `disabled` 完成摘要验收。

管理员接口：`PUT /api/admin/models/providers/{provider_id}`。

```json
{"base_url": "http://model-server:8080/v1", "api_key": "", "thinking_mode": "disabled"}
```

明确清除已有 Key：

```json
{"clear_api_key": true}
```

| 错误码 | 含义 |
| --- | --- |
| `ERR_EMBEDDING_DIMENSION_MISMATCH` | 实际维度与 768 不符，错误中列出期望 / 实际维度 |
| `ERR_EMBEDDING_INVALID` | 空向量、缺失向量或非法分量，同样报告维度信息 |
| `ERR_AI_EMPTY_SUMMARY` | 模型没有返回可用摘要正文，包括空正文且 `finish_reason=length` |
| `ERR_AI_TIMEOUT` | 摘要请求超过时间上限 |
| `ERR_AI_UNAVAILABLE` | 摘要服务连接或上游 API 请求失败 |

模型客户端连接超时 5 秒，单次请求超时 120 秒，SDK 自动重试最多 1 次；摘要调用整体上限 180 秒，覆盖重试等待。任务级恢复仍由原有状态与调度机制处理，不新增状态。冒烟脚本不自动重试，单次默认 120 秒，也受摘要整体上限约束。

[真实拒绝记录](v0.3.1-dimension-rejection.jsonl)：两个供应商请求 `qwen-embedding` 均得到上游 HTTP 200、1024 维结果，但 Pekno 返回 `ERR_EMBEDDING_DIMENSION_MISMATCH`，记录为 `interface_success=true`、`storage_compatible=false`、期望 768、实际 1024，脚本预期以非零退出码结束。此次没有启用数据库写入。

### 复现

先准备已通过现有 Alembic 迁移的隔离数据库，通过 `POSTGRES_*` 环境变量连接：

```bash
uv run --no-sync python scripts/smoke_model_providers.py \
  --base-url http://MODEL_HOST:PORT/v1 --model qwen9b \
  --embedding-model nomic-embedding --thinking-mode disabled --database-roundtrip
```

`--database-roundtrip` 会实际提交唯一命名的测试用户及文档，查询后删除；省略时不写入业务数据库。可重复指定 `--provider`、`--purpose` 复测部分路径。认证服务通过 `--key-env PEKNO_SMOKE_API_KEY` 指定已配置的环境变量，脚本不打印 Key。
